# 하얀 부엉이 저택 사건 (v2, 블록 스타일) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** v1 「말랑 산장」을 대체하는, 2층 블록(복셀) 저택에서 4명이 폰으로 40분간 플레이하는 크라임씬 「하얀 부엉이 저택 사건」을 만든다.

**Architecture:** 빌드 없는 ES 모듈. 순수 로직(`src/core/*`: 맵 데이터 검증, 충돌 격자, 길찾기, 게임 규칙 리듀서)은 THREE를 import하지 않아 Node 내장 테스트 러너로 테스트한다. 렌더/입력/네트워크/UI(`src/*.js`)는 core를 쓰고 브라우저에서 검증한다. 멀티는 v1과 같은 PeerJS 방장-권한 스타 구조이며, 방장이 `core/rules.js`의 `applyAction`으로 상태를 바꾸고 전체 상태를 방송한다.

**Tech Stack:** Three.js 0.160.0 (unpkg importmap), PeerJS 1.5.4 (unpkg), Node 20 `node --test` (테스트 전용, 의존성 설치 없음), GitHub Pages(main 루트).

**Spec:** `docs/superpowers/specs/2026-11-21-mansion-v2-design.md`

## Global Constraints

- 외부 3D 모델·이미지 다운로드 없음. 모든 블록·텍스처·캐릭터는 코드로 생성
- 마인크래프트 실제 텍스처·캐릭터(스티브, 크리퍼 등)·로고 사용 금지 — 자체 픽셀 스타일
- 큰 블록 1칸 = 0.5m, 미니 블록 = 0.125m, 텍스처 16×16 px + `THREE.NearestFilter`
- 층 하나 기준 드로우콜 목표 100 이하 (같은 블록 종류는 `InstancedMesh`)
- 중급 안드로이드 30fps 이상, 와이파이 첫 로딩 10초 미만
- 방 10개 이상, 2개 층, 방마다 소품 15~30개
- 진행: 대기실 → 사건 소개 → 조사1 12분(1층) → 중간 토론 5분 → 조사2 10분(2층 열림) → 최종 토론 8분 → 투표 → 진상
- 인원: 2명 이상이면 범인(sera)은 반드시 플레이어. 빈 역할은 NPC 진술서. 5명째부터 조수 탐정(helper)
- 증거: `kind:'fixed'`는 챙길 수 없음, `kind:'portable'`은 챙기면 다른 사람은 못 봄
- 비밀 통로: sera·doyun은 처음부터 사용 가능, 나머지는 서재 `oddbook` 조사로 발견, 공유하면 모두 사용
- 재접속: 같은 방 코드로 다시 들어오면 같은 캐릭터 (localStorage `owl-pid`)
- `src/core/*`는 `three`나 DOM을 import/참조하지 않음
- 모든 화면 문구는 한국어
- `index.html`은 v2로 교체 (v1은 git 기록에 남음)
- 로컬 미리보기: 이 Mac에서는 python 서버가 `~/Documents`를 못 읽음(macOS 권한). 미리보기는 저장소를 세션 scratch의 `site/`로 복사해 `.claude/launch.json`의 `mystery-room` 서버로 띄운다

## Review Focus

1. **플레이어가 조사 중에 끊겼다가 재접속** — 같은 역할·챙긴 증거·투표가 그대로여야 함 → Task 3 `rejoin keeps role and items` 테스트
2. **범인이 휴대 증거를 전부 챙겨 숨김** — 고정 증거만으로도 범인까지 추리 가능해야 함 → Task 2 `every chain has a fixed-only path` 테스트
3. **2층이 닫힌 조사1 단계에서 계단을 탭함** — 2층으로 가지 않고 "2층은 조사2부터 열려요" 토스트 → Task 3 `stairs blocked before investigate2` 테스트 + Task 4 `findPath respects floorsOpen`
4. **2~3명만 접속** — sera가 항상 플레이어, 빈 역할은 NPC 진술서 표시 → Task 3 `culprit always assigned to a player when 2+`
5. **투표 동점 / 미투표자** — 동점이면 "범인이 빠져나갔다", 끊긴 사람은 투표 대상 인원에서 제외 → Task 3 `tally tie means not caught`, `offline players excluded from vote count`

### Task 3: 게임 규칙 리듀서

**Files:**
- Create: `src/core/rules.js`, `tests/rules.test.js`

**Interfaces:**
- Consumes: `CASE` 형식 (Task 2)
- Produces:
  ```js
  // State = { phase, phaseEndsAt, players:{[pid]:{name, role, online, floor, x, z, ry, mv}}, order:[pid],
  //   items:{[id]:{holder:pid|null, shared:boolean}}, passageKnown:{[pid]:true}, passageShared:boolean,
  //   votes:{[pid]:roleKey}, floorsOpen:number[] }
  createState(caseData) -> State
  applyAction(S, caseData, action, fromPid, now, rng=Math.random) -> { S, events:Event[], private?:{[pid]:Event[]} }
  //   action.t ∈ 'join'{name} | 'leave' | 'pos'{floor,x,z,ry,mv} | 'next' | 'pick'{id} | 'share'{id}
  //              | 'discoverPassage' | 'sharePassage' | 'vote'{target} | 'useStairs'{id} | 'usePassage'
  //   Event = {type:'toast', text} | {type:'phase', phase} | {type:'teleport', pid, floor, x, z}
  assignRoles(pids, caseData, rng) -> {[pid]:roleKey}
  canUsePassage(S, caseData, pid) -> boolean
  visibleItem(S, pid, itemId) -> 'present' | 'mine' | 'shared' | 'gone'
  tally(S, caseData) -> { counts:{[roleKey]:n}, top:roleKey[], caught:boolean, voters:number }
  ```
- 규칙: `next`는 `fromPid==='host'`만. 단계 진입 시 `phaseEndsAt = now + ms`, `floorsOpen = phase.floors`. intro 진입 시 역할 배정 + 전원 hall로 teleport 이벤트. 시간 경과 자동 진행은 호출자(net)가 `next`를 host 이름으로 보냄
- `join`: 이미 있는 pid면 `online=true`만 (재접속). 새 pid가 lobby 이후면 남은 역할 → 없으면 helper
